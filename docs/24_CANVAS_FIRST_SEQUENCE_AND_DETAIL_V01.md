### 세 구간의 서로 다른 역할

| 구간 | 방문자가 알아야 하는 것 | 배치의 주인공 | 다음 행동 |
|---|---|---|---|
| `#entry` | 무엇을 다루는 브랜드이고 어디로 들어갈까 | 하나의 현재 Issue와 큰 편집 사건 | Issue 읽기 / 공방 안내 |
| `#issues` | 어떤 글을 읽을까 | 대표 Article과 실제 보조 항목 | Article 읽기 |
| `#scents` | 이 향은 무엇이며 더 읽거나 받을 수 있을까 | 선택된 Dossier와 관련 맥락 | Dossier 보기 / 제공 안내 |

현재 Issue 표지를 두 번 반복하지 않는다. 같은 Article을 복제해서 구간마다 다른 글처럼 보이게 하지 않는다. 같은 엔티티의 짧은 연결 링크는 허용하되, 본문과 대형 카드를 불필요하게 재등장시키지 않는다.

## 3. 첫 세 구간의 연속 배치

아래는 영역 관계와 DOM 읽기 순서에 대한 도식이다. 정확한 좌표, 열 수, 크기 비율, 색과 서체는 아니다. A/B 등의 표시는 구현 슬롯 이름이며, 실제 콘텐츠 제목으로 출력하지 않는다.

```text
[공식 워드마크]                 매거진  향  원료  공방  목차

#entry
  A. Issue 종류·번호
  B. 큰 제목이 시각 영역을 가로지름
       [V1: 주 편집 이미지 영역]
              [V2: 경계를 넘는 보조 시각층]
  C. AFTON이 다루는 내용 한 문장
  D. 이슈 읽기           E. 공방 안내 · 서비스 준비 중
                              [다음 글의 제목/일부가 이어짐]

#issues
  F. 대표 Article                       G. 보조 항목, 있을 때
     종류 / 완전한 제목                    종류 / 제목
     [기사 시각 영역]                       간단한 소개 / 링크
     소개 / 기사 읽기
  H. 현재 Issue 목차
                         I. 실제 관계가 있는 향으로 이동

#scents
  J. 향 제목과 설명을 읽는 안정된 영역
  K. 관련 Article / 공개 Record / Material 중 실제 연결된 항목
                  [겹침과 연결 표현은 K 주변에서만]
  L. Dossier 보기       M. 제공 상태 / 샘플 안내
                     [다음 원료 구간으로 이어지는 관계]
```

### 공간 연결 방식

- Entry와 Editorial 사이: 시각 이미지나 장식 글자의 일부만 구간 경계를 넘는다. 다음 Article의 완전한 제목과 링크는 자기 영역에 있다.
- Editorial과 Scents 사이: 실제로 관련된 향에 대한 짧은 문장과 링크가 연결을 만든다. 장식 연결선만 놓고 관계를 추측하게 하지 않는다.
- Scents와 Materials 사이: 검증된 관련 원료 또는 감각적 참조가 있을 때만 연결한다. 없으면 일반 원료 구간 이동 링크와 해당 구간의 빈 상태를 사용한다.
- 양옆에서 잘리는 것은 장식층 또는 의미 없는 이미지 가장자리다. 핵심 콘텐츠를 화면 밖에 숨겨 큰 캔버스 느낌을 만들지 않는다.
- 세 구간을 각각 정확히 한 화면 높이에 맞추지 않는다. 실제 텍스트가 길어지면 다음 구간이 자연스럽게 밀린다.

## 4. 슬롯별 콘텐츠와 동작 계약

| 슬롯 | 데이터 근거 | 클릭/선택 | 없는 경우 |
|---|---|---|---|
| A/B | 현재 Issue의 번호·제목 | 제목 또는 별도 링크가 Issue로 이동 | 임의 발행물 대신 정직한 소개·empty state |
| C | 검토된 사이트 소개 | 일반 문장 | 후보 문구로 표시하거나 생략 |
| D | 표시 가능한 Issue | canonical Issue URL | 가짜 `#` 링크를 만들지 않음 |
| E | 구현된 공방 안내 | `/#workshop` 또는 유효한 `/info/#workshop` | 실행되지 않는 예약 버튼 대신 안내를 준비 중으로 표시 |
| F | Issue가 순서대로 소유한 실제 Article | canonical Article URL + 유효한 Issue 맥락 | 대표 기사가 없으면 해당 Issue의 상태 표시 |
| G | 중복을 제거한 나머지 실제 Article | 해당 Article로 이동 | 빈 콘텐츠 카드를 넣지 않음 |
| H | 같은 Issue의 실제 목차 | 실제 Issue 페이지 또는 로컬 목차 | 한 글이면 한 항목 |
| I | F와 명시적으로 관련된 ScentDossier | 해당 Dossier로 이동 | 독립 기사면 연결 문장 자체 생략 |
| J | 선택된 ScentDossier | 전체 Dossier로 이동 | 정직한 향기 기록 empty state |
| K | 해당 향의 실제 관계를 조회한 목록 | 요약 펼치기 또는 명시된 상세 링크 | 관계 영역 생략 |
| L | 선택된 ScentDossier | canonical Dossier URL | 대상 없음 처리 |
| M | Product / 유효 Availability | 내부 제공·샘플 안내만 | Product 없음과 unknown을 구분 |
| V1/V2 | 사용 범위가 승인된 자산, 있으면 사용 | 장식이면 비조작 | 리뷰 전용 슬롯 표기 또는 구조만 유지 |

한 타일 안에 타일 전체 링크와 다른 링크/버튼을 중첩하지 않는다. 카드가 두 행동을 가진다면 이미지/제목 링크와 요약 버튼을 별도로 구분한다.

## 5. 눌렀을 때의 세 가지 동작

### 5.1 전체 글을 읽기: 주소가 있는 페이지

`이슈 읽기`, `기사 읽기`, `향기 기록 보기`는 기존 다섯 화면의 실제 링크다. 본문 전체를 필수 팝업으로 열지 않는다. 새 탭, 직접 URL, 뒤로가기를 막지 않는다.

큰 캔버스는 발견을 위한 장소다. 글을 읽는 동안에는 본문 뒤로 카드가 지나가거나 다른 기사들이 자동 이동하지 않는다. 전체 사이트의 맥락은 상단 정보와 관련 링크로 유지한다.

### 5.2 관계를 훑기: 한정된 인라인 미리보기

공개 가능하고 존재하는 관계가 있을 때만 `요약 펼치기` 버튼을 제공한다. 기본 상태에서는 대상 이름, 종류, 연결 이유와 정규 링크가 이미 보인다. JavaScript가 없으면 이 목록과 링크가 그대로 동작한다.

상태:
- `idle`: 관계 목록과 직접 링크가 보인다.
- `selected`: 선택한 한 항목의 요약이 안정된 상세 영역에 보인다.
- `idle`로 복귀: `요약 닫기`로 접고 선택 버튼으로 초점을 돌린다.

선택은 페이지 안의 정보 표시일 뿐이다. 설계 연산·개인 프로필 생성·취향 저장·예약을 호출하지 않는다. 관계 선택마다 브라우저 방문 이력을 추가하지 않는다.

요약이 열렸을 때 작은 화면에서는 상세 영역의 제목으로 초점을 옮겨 발견할 수 있게 하고, 닫았을 때 원래 버튼으로 복귀한다. 마우스 hover만으로 선택하지 않는다. 링크 실행과 요약 선택을 서로 다른 행동으로 유지한다.

### 5.3 안내를 읽기: 공방·샘플은 정보 페이지

공방 링크는 계획된 서비스를 설명하는 영역으로 이동한다. 모든 카테고리를 스크롤해야만 접근할 수 없도록 첫 탐색에서 노출한다.

`/info/#workshop`은 아직 구현되지 않았다면 먼저 구현하고 검증한다. 주문·예약·설문 제출·실제 후보 계산은 넣지 않는다. 선결제 이후 연구를 시작하는 사업 순서는 23번을 보존한다.

## 6. 상세 화면 구성

### Issue: 글을 선택하는 목차

```text
[Home의 매거진으로]
Issue 종류·번호
h1: Issue 제목
소개, 존재하는 발행 정보

순서가 있는 실제 Article 목록
관련 대표 향, 있을 때
[다시 매거진 보기]
```

Home 표지를 그대로 한 번 더 전체 높이로 재생하지 않는다. 이미 표지를 보고 들어온 방문자가 이번에는 읽을 글을 선택할 수 있어야 한다.

### Article: 읽기가 중심인 편집면

```text
[유효한 Issue 맥락]              [전체 목차]
h1: Article 제목
요약 / 검증된 필자·날짜
[승인된 이미지, 있을 때]
본문

[이 글과 연결된 향, 실제 관계가 있을 때]
[다음 실제 글]                  [목차 또는 매거진으로]
```

대형 제목과 이미지가 만나는 강한 시작은 가능하다. 본문에 들어오면 읽을 영역을 안정적으로 유지한다. 날카로운 리뷰·업계 기사라도 실제 시향/발표자료 요약/외부 리뷰 정리/칼럼을 구분한다. 본 문서는 실제 시장 평가나 새 원료 사실을 추가하지 않는다.

### Scent Dossier: 하나의 향과 관계의 깊이

```text
h1: 향 이름
확인되었거나 명확히 후보로 표시된 소개
처음 / 중심 / 여운: 설명이 있는 항목만

[향을 중심으로 한 관련 카드와 읽을 수 있는 상세 영역]
  기사 / Material / 공개 Record / Object, 실제 관계만

개발 상태, 있으면 표시
제품 형식과 제공 상태
[샘플 안내 읽기]                [관련 글 / 향 목록으로]
```

개발 상태, 발행 상태, 제공 상태를 별개의 정보로 둔다. 외형이 원료 그래프처럼 보인다고 실제 처방·함량·재고 정보를 노출하지 않는다. 감각적 참조는 실제 성분과 구별한다.

## 7. 돌아가기와 맥락

기존 제안 경로 `/`, `/issues/[slug]/`, `/articles/[slug]/`, `/scents/[slug]/`, `/info/`를 재사용한다. 새로운 공개 경로를 이 문서 때문에 만들지 않는다.

- Home의 `#entry`, `#issues`, `#scents`, `#materials`, `#workshop`, `#records`, `#perspectives`는 23번의 anchor다.
- 부분 구현 중 아직 없는 구간으로 연결하지 않는다. 예를 들어 공방은 검증된 Info 안내로 먼저 연결할 수 있다.
- Article의 `issue` 맥락은 해당 Issue에 실제 수록된 기사일 때만 수용한다.
- 직접 진입한 Article에 이전 방문 경로를 만들어 붙이지 않는다. 수록호가 여럿이면 해당 목록을 보여준다.
- 뒤로가기는 브라우저의 기본 복원 동작을 존중한다. 모든 진입 때 맨 위로 강제 이동하지 않는다.
- 별도의 `매거진으로` / `향 목록으로` 링크는 `/#issues` / `/#scents`처럼 검증된 위치를 제공한다. 명시된 지역으로 돌아가는 것과 이전 스크롤의 정확한 복원을 동일한 보장으로 말하지 않는다.
- 이 단계에 쿠키·계정·localStorage 방문자 이력은 필요하지 않다. 세션을 넘어 취향을 기억하는 기능은 만들지 않는다.

## 8. 모바일과 입력 방식

Desktop의 비대칭 배치와 Mobile의 읽기 순서는 같은 콘텐츠 의미를 공유한다. 모바일은 데스크톱 한 장을 작게 축소한 것이 아니다.

| Desktop 역할 | Mobile 재구성 |
|---|---|
| 큰 제목과 겹친 시각층 | 완전한 제목·설명·링크를 먼저 읽고 시각층이 이어짐 |
| 대표 Article + 보조 항목 | 대표 다음 보조 순서, 빈 보조 자리는 삭제 |
| 향 주위의 관계 | 향 설명 → 관련 목록 → 선택 요약 |
| 가장자리 잘린 이미지 | 장식 범위만 crop, 제목과 링크는 자르지 않음 |
| 상시 인덱스 | 읽을 수 있는 간결한 메뉴/목차, 기본 접힘 가능 |

한 페이지에서 스크롤·drag·zoom을 동시에 요구하지 않는다. 효과 없는 상태에서도 모든 의미와 링크가 남는다. `현재 위치` 표시는 구간 위치를 뜻하며 개인 향 설계의 완료율이 아니다.

## 9. 데이터·구성·자산의 분리

코어 엔티티를 재정의하지 않는다. Home의 배치 설정은 이미 존재하는 엔티티 ID를 참조하며, 순서와 역할만 추가한다.

최소 구성 역할 제안:
- `currentIssueRef`: 현재 표지로 보여줄 Issue.
- `leadArticleRef`: 위 Issue의 유효한 Article 중 하나. 지정이 없으면 기존 순서를 따른다.
- `supportArticleRefs`: 중복을 제거한 실제 보조 Article 목록.
- `featuredScentRef`: 대표 Article의 연결 향 또는 편집자가 명시적으로 선택한 향.
- `bridgeReason`: 왜 연결되는지에 대한 검토된 문장. 자동 추론으로 작성하지 않는다.
- `assetSlots`: 콘텐츠 ID와 별개의 선택 자산 참조. 미선정은 null이다.

대표 기사가 독립 기사인 경우에도 별도로 향 구간은 존재할 수 있다. 두 내용 사이에 관계가 있다는 표현은 하지 않는다.

`default order`는 방문마다 무작위로 바꾸지 않는다. 검토 결과를 반복 재현할 수 있게 같은 입력은 같은 배치를 만든다.

두 리뷰 모드를 분리한다:
- Functional sparse view: 한 Issue·한 Article·한 Dossier로도 실경로를 검증한다.
- Layout stress fixture: 필요 시 명백히 `LAYOUT TEST ONLY`인 합성 긴 제목과 여러 슬롯으로 배치 내구성만 검사한다. 실제 향 이름·실험 결과·관찰·저자를 만들어 넣지 않고 공개 빌드 데이터와 완전히 분리한다.

실제 콘텐츠가 적다고 같은 Article을 여러 ID로 복제하지 않는다. 기능적으로 빈 상태를 처리한 것과 풍부한 매거진 무드가 검증된 것은 서로 다르다.

## 10. 자산 준비 계약

이미지 원본 중 일부가 만료되어 실제 추출·크롭은 재업로드 이후 작업한다. 무드 선택 이미지 자체를 현재 공개 가능한 웹 자산으로 승격하지 않는다.

필요한 자산 역할만 먼저 확보한다:

| 역할 | 목적 | 미선정 시 |
|---|---|---|
| 기존 공식 워드마크 | 브랜드 식별 | 새 로고 생성/근사 금지 |
| Entry 주 시각층 | 제목과 결합하는 표지 구성 | 리뷰 전용 영역 표시 |
| Entry 보조 시각층 | 겹침·가림·색면 관계 | 없어도 구조 유지 |
| Article 대표 이미지 | 실제 글을 설명하는 시각 역할 | 텍스트형 teaser |
| Dossier 관련 이미지 | 선택 항목의 맥락 | 정보 카드만 표시 |

후보 자산을 사용할 때 원본 위치, 허용된 사용 범위, 크롭 초점, 역할, 대체텍스트, 승인 상태를 기록한다. 레퍼런스-only 파일이나 이전 제외 이미지 6개를 슬롯 대체물로 가져오지 않는다. 생성 이미지 안의 깨진 글자·임의 로고·가짜 제품을 별도 DOM 콘텐츠로 재사용하지 않는다.

이번 구조에서 원색은 허용되는 표현 방향이다. 특정 HEX, 서체, 최종 곡선이나 그래픽은 결정하지 않는다. 사진 사용 여부도 자연주의/인물이라는 범주만으로 단정하지 않고 실제 선택된 이미지의 편집 역할을 판단한다.

## 11. 최소 구현 인계

기존 동등 컴포넌트를 먼저 찾아 재사용한다. 이름은 제안이며 새 파일이 존재한다는 뜻이 아니다.

| 역할 | 책임 |
|---|---|
| EditorialCanvas / CanvasZone | 정상 문서 흐름, 구간 anchor, 장식층과 읽기층 분리 |
| IssueCover | A~E, 하나의 표지와 명확한 진입 |
| FeatureCluster | F~I, 실제 글의 위계와 향 연결 |
| ScentCluster | J~M, Dossier·관계·제공 상태 |
| RelationView | 기존 관계 목록, 선택 요약, 정규 링크 |
| ContextReturn | 실제 수록 맥락과 기본 복귀 링크 |

첫 전달물은 모든 기능을 다 만든 사이트가 아니라 다음의 작은 작동 경로다:

`Home 첫 세 구간 → Article 한 편 → Scent Dossier → Info`, 그리고 `Home → Issue → Article`과 `Home → 공방 안내`.

가능한 수준부터 정적 구조로 구현한다. 브라우저를 가로지르는 장식층은 텍스트 링크 위에서 pointer 이벤트를 받지 않는다. 본문을 하나의 거대한 bitmap이나 HTML canvas로 대체하지 않는다. 무조건 WebGL·force graph·영상·always-running loop를 추가하지 않는다.

원본 이미지는 모두 선로드하지 않는다. 실제 구현 후 현재 측정 문서를 찾아 이미지/JS 전송량, 가로 넘침, layout shift, 좁은 화면 동작을 기록한다. 이 문서는 성능 목표를 측정 결과로 제시하지 않는다.

## 12. 이번 슬라이스 수용기준

1. 표지는 한 번만 나타나고, 그다음에는 실제 기사와 향으로 이어진다.
2. 모든 실제 제목·본문·링크는 DOM 텍스트다. 이미지와 효과를 꺼도 읽고 이동할 수 있다.
3. 하나의 시각층이 다음 구간과 연결되어도 의미 있는 텍스트·클릭 대상이 가려지지 않는다.
4. 큰 캔버스는 강제 가로 스크롤·drag·확대 없이 아래로 탐색된다.
5. 한 Article 데이터에서도 유효한 Home·Issue·Article·Dossier 경로를 만든다.
6. 존재하지 않는 보조 기사·원료·제품·관계선을 만들어 화면을 채우지 않는다.
7. Article 대표 링크는 전체 글로, 관계 요약 버튼은 인라인 상세로 구분된다.
8. 관계 선택은 원본 엔티티·개인 정보·예약 상태를 변경하지 않는다.
9. 직접 URL, 새 탭, 브라우저 뒤로가기, 유효/무효 Issue 맥락을 확인한다.
10. 공방은 상단에서 접근되지만 온라인 예약·결제·실제 계산이 작동하는 것처럼 표시하지 않는다.
11. unknown 제공 상태를 sold out/available로 바꾸지 않는다.
12. 모바일에서도 같은 핵심 콘텐츠와 모든 이동 수단을 사용할 수 있다.
13. 키보드, focus 복귀, logical headings, skip link, 이미지 없음, 긴 한글/영문 제목을 확인한다.
14. motion 없이 먼저 검증하고 reduced-motion을 존중한다. 빠른 깜빡임·반복 고대비 진동을 추가하지 않는다.
15. private context·처방·고객 데이터·reference-only 자산·합성 stress fixture가 공개 대상에 섞이지 않는다.
16. 실제 `check / build / tests`, tested SHA와 PC·모바일 렌더 또는 실행 불가 사유를 기록한다. 예전 PR의 검사 결과를 재인용해 통과라고 하지 않는다.

## 13. Codex 전달과 남은 경계

Codex는 기존 코어 작업을 계속하면서 이 문서를 첫 상단 슬라이스의 상세 기준으로 사용한다. 계획 문서를 더 작성하는 것으로 구현 산출물을 대신하지 않는다. 현재 사용자 승인 대상으로 다시 올릴 것은 레퍼런스 이름이 아니라 적용된 실제 화면의 무드다.

기록 형식: tested SHA / 변경 파일 / 로컬 경로 / 실행한 검증 / 미실행 항목 / 막힌 점 / 다음 담당.

이 문서 작성 시 확인한 PR #1은 open, unmerged, mergeable=false다. 이는 읽기 시점의 상태이지 영구 상태가 아니다. 기준 동기화와 충돌 정리는 별도 Codex 검토 대상으로 남긴다. 이 인계를 이유로 강제 push·병합·배포를 수행하지 않는다.

이번 웹 GPT 변경은 상세 구성 명세 한 파일이다. 앱 코드 수정·화면 렌더·테스트·타이머 시작을 수행했다고 보고하지 않는다. Git 인계가 Codex 자동 실행이나 진행 확인을 뜻하지 않는다.
