개인 방문 리뷰는 힌지앤룰 디자인이 주 계정이다. 그곳에서 실제로 독립 작품을 만들었다면 UNSEEN RATIO로 연결할 수 있다. 제작 계약이 없는데 힌지앤룰 오피셜의 작업 사례로 쓰지 않는다. AFTON과 관계가 없으면 AFTON은 발행하지 않는다.

개인의 관찰·해석은 힌지앤룰 디자인에, AFTON의 공식 편집 의도로 채택한 별도 원고는 AFTON 매거진에 둔다. 자료 정리와 직접 시향 리뷰를 구분한다. 감각적 재해석이 독립 작품으로 성립할 때만 UNSEEN RATIO 파생본을 만든다. 객관적 성분·효능·성능을 원고 변환 과정에서 새로 만들어내지 않는다.

## 6. 업무량과 운영 우선순위

사용자가 네 계정의 상시 편집자가 되는 구조를 피한다. 운영의 제안 우선순위는 다음과 같다.

1. 이미 약속한 제작·고객 대응과 실제 수행 가능한 목공 수익 업무를 보호한다.
2. AFTON의 현재 웹 코어·첫 클릭 경로라는 기술 작업을 유지한다.
3. 실제 작업에서 생긴 소재 가운데 중요한 콘텐츠 묶음 하나를 준비한다.
4. 관련성과 여력이 있을 때에만 다른 계정 파생본을 만든다.

기존의 기술 슬라이스 한 개 + 콘텐츠 묶음 한 개라는 진행 제한은 계속 사용한다. 실제 제작·고객 업무를 이 두 작업에 더해 무제한으로 넣는다는 뜻이 아니다. 제작 일이 늘면 파생 콘텐츠와 실험 작업량을 줄인다.

발행 빈도는 계정별 할당량이 아니다. 초기 공통 묶음 1~2주에 한 개라는 이전 제안은 전체 편집 준비량의 출발점일 뿐, 계정마다 주 1~2개를 추가하는 계획이 아니다. 실제 운영 시간을 기록한 뒤 조정한다. 같은 날 동시 발행, 9칸 채우기, 매일 릴스·스토리, 상시 라이브·광고를 의무로 하지 않는다.

힌지앤룰 오피셜은 실제 문의와 제작 소식이 있을 때 적시에, 개인 계정은 가치 있는 글이 준비됐을 때, UNSEEN RATIO는 작품·시리즈 단위로, AFTON은 검토된 발행물·제품·서비스 단위로 운영하는 리듬을 제안한다.

성과 확인도 구분한다. 오피셜은 적합한 문의·수주·투입 시간, 개인 계정은 글에 대한 유의미한 질문·재참조, 아티스트 계정은 작품 반응·협업 문의, AFTON은 관련 기사·향·공방 안내로의 관심과 실제 운영 이후의 참여를 본다. 아직 수치를 측정하거나 목표를 확정한 것은 아니다. 각 플랫폼이 지원하는 확인 범위 안에서만 기록하고 새 추적 SDK를 요구하지 않는다.

## 7. 기존 계정 전환 계획

역할 결정과 실제 프로필 변경은 구분한다. 확인할 최소 등록 항목은 정체성명, 실제 handle/URL, 소유·접근 상태, 현재 역할, 목표 역할, 연결할 블로그·사이트, 문의 담당이다. 알 수 없는 값은 미확정으로 남긴다.

`unseenratio`와 `sumboy_v_and_v`는 앞서 대화에 나온 문자열일 뿐, 현재 공식 핸들과 각 역할의 대응을 이번 계획에서 검증한 것은 아니다. 계정명을 추정해서 사이트에 연결하거나 다섯 번째 계정을 임의로 추가하지 않는다.

향후 실행 순서 제안:

- 기존 계정과 공개 프로필을 읽고 사용 중인 목적을 확인한다.
- 계정별 소개문과 고정 안내, 문의 목적지를 초안으로 만든다.
- 힌지앤룰 디자인의 개인 전환 과정에서 기존 제작 문의가 길을 잃지 않도록, 실제로 확인된 오피셜 목적지로 안내하는 전환 문안을 마련한다.
- 과거 게시물은 계정 의미가 바뀌었다는 이유만으로 삭제·숨김·재게시하지 않는다. 과거 작업의 설명과 권리도 임의로 바꾸지 않는다.
- 실제 이름·핸들·프로필·고정 게시물 변경은 별도의 계정 작업 요청과 권한이 확인된 뒤 한다.

## 8. 분업·검증·공개 경계

| 담당 | 책임 |
|---|---|
| 사용자 | 실제 경험·제작·작품의 원천, 최종 무드, 본인 확인이 필요한 계정 조치 |
| 웹 GPT | 계정 정체성 유지, 소재 배분, 원고·캡션·블로그 초안, 출처·사실·의견 구분 |
| Codex | 기존 웹 코어·링크·테스트·Git 기록, 최소 콘텐츠 내보내기 구조, 상태·버전 검증 |

이미 결정된 정보구조나 통상적인 문장 편집을 매번 사용자에게 되묻지 않는다. 누락된 실제 경험이나 계정 권한을 모델 추론으로 대신하지 않는다.

개인 계정에 글을 게시한다는 결정은 기존 비공개 성향 분석, 생애 기록, 가족·재무·건강·고객·처방 자료를 공개하라는 허가가 아니다. 의도적으로 선택된 공개용 원고만 준비한다. 개인 채널의 의견은 자동으로 공식 브랜드 입장이 되지 않는다.

이 AFTON 웹 저장소에는 채널 역할과 연계 정책, 공개 가능한 AFTON 콘텐츠 및 계약만 둔다. 다른 계정의 전체 개인 기록·매출 운영 DB·비공개 작품 원본·계정 토큰을 통합 보관하지 않는다. 공용 비공개 운영자료의 저장 위치는 별도 결정이며 새 저장소나 플랫폼을 임의로 만들지 않는다.

무드 승인, 사실 검증, 사용 자산 확인, 외부 발행 권한을 별도로 관리한다. 이번 역할 결정은 계정 생성·프로필 변경·자동 발행 허가가 아니다. 향후 게시 정책을 정할 때 검토된 묶음과 채널별 허용 범위를 함께 정해 반복 승인 부담을 줄인다.

## 9. 최소 콘텐츠 기록 제안

새 CMS·DB·SNS 연동부터 만들지 않는다. 기존 문서나 AFTON 콘텐츠 계약에서 필요한 항목만 재사용한다.

| 항목 | 역할 |
|---|---|
| source_id / source_version | 공통 사실·관찰 묶음 참조. 비공개 원문을 웹 빌드에 포함하지 않음 |
| editorial_owner | hinge_rule_official / hinge_rule_design / unseen_ratio / afton. 실제 핸들이 아닌 내부 역할 식별자 |
| content_intent | 제작 사례·개인 분석·감각 작품·브랜드 발표 등 발행 목적 |
| primary_channel | 이번 원고의 주 채널 |
| derivatives | 가치가 다른 파생 초안만. 생략 가능 |
| evidence_status | 확인된 사실·직접 관찰·출처 기반 정리·해석·후보 구분 |
| asset_refs | 사용할 수 있는 자산과 출처·승인 상태 |
| primary_destination | 검증된 주 목적지 하나 또는 없음. 미구현 링크 금지 |
| relation_disclosure | 자기 사업·제품·협업 관련성 등 독자가 알아야 하는 맥락 |
| channel_state | not_started / draft / needs_verification / ready_for_review / ready_to_publish / published / on_hold |
| publication_receipt | 실제 published일 때만 공개 URL·시각·발행 원본 버전 |

파생본 승인·게시 상태는 채널마다 독립적이다. 하나의 posted 상태를 다른 계정에 복제하지 않는다. 원본의 사실이 수정되면 관련 파생본만 재검토한다. 수정 완료와 실제 외부 수정 반영도 구분한다.

편집 기록 항목과 AFTON 공개 웹 엔티티를 구분한다. 이 제안 때문에 개인 계정의 모든 소재를 공개 사이트의 Article 레코드로 넣지 않는다.

## 10. 다음 산출물과 완료 기준

기술 작업은 기존 22번 코어와 24번의 Home 첫 세 구간·실제 클릭 경로를 유지한다. 네 계정을 동시에 운영할 소셜 플랫폼이나 API부터 개발하지 않는다.

다음 편집 작업은 새 전략 문서가 아니라 계정별 짧은 소개문·상단 고정 안내 초안과, 실제 소재 하나의 주 계정·필요 파생본을 지정한 편집 패키지다. 실제 작업·방문·시향 근거가 없으면 경험담을 채워 넣지 않는다.

완료 기준:

1. 힌지앤룰 오피셜과 힌지앤룰 디자인을 사업 채널과 개인 저자 채널로 정확히 구분한다.
2. UNSEEN RATIO가 독립 아티스트 정체성을 유지하고 AFTON이 공식 브랜드 판단을 유지한다.
3. 블로그의 글 주체와 AFTON 웹 원고를 구분한다. 새 블로그 개수를 임의로 늘리지 않는다.
4. 한 소재를 네 번 복제하지 않고 주 계정과 필요한 파생본만 선정한다.
5. 실제 계정 핸들·소유·링크 미확정 상태를 그대로 남긴다.
6. 계정·고객·비공개 자료와 공개 웹 데이터의 경계를 지킨다.
7. 현재 웹 구현이 계정 운영 계획 때문에 중단되지 않는다.
8. 계정 변경·외부 발행·생성·크레딧·병합·배포는 기존 HOLD를 유지한다.
