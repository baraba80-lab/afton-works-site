## 1. 사용자 결정과 문서 역할

사용자 최신 요청: 전체 큰 그림을 먼저 완성하고 그 안에서 세부 설계로 들어간다. AFTON 메인 Instagram과 블로그 운영을 계획에 추가한다. 운영 부담이 이미 크므로 채널 수만큼 독립적인 제작 업무를 늘리지 않는다.

확인 기준: 후보 브랜치 `codex/afton-landing-v0-1`, HEAD `e9ff31a20f746350df0174a2146daefcb1a82ea4`. 이번에 읽은 문서는 `AGENTS.md`, `CODEX_TASK.md`, `docs/24_CANVAS_FIRST_SEQUENCE_AND_DETAIL_V01.md`다. 이전 인계 22번의 비시각 코어와 23~24번의 편집 캔버스 구성을 이어받는다.

이 문서는 사이트와 외부 채널의 역할·제작 흐름·업무량을 정리한 계획 추가다. 새 앱 코드, 계정 개설, 게시물 발행, 자동화 실행, 플랫폼 연결, 타이머 설정을 수행한 보고가 아니다. CODEX_TASK의 현재 구현을 중단시키거나 다시 전략 수집부터 시작시키지 않는다.

이하 주기·업무량·채널별 구성·순서는 제안이다. 플랫폼 알고리즘, 검색 노출 성과, 실제 계정 존재, 실제 상품이나 서비스 제공 여부에 관한 검증된 사실로 취급하지 않는다.

개인 성향·창업자 배경 자료는 협업 참고용으로만 사용한다. 이를 브랜드 소개, 계정 소개, 블로그 글, 고객 스토리로 변환하지 않는다.

## 2. 전체 운영 지도

각 영역의 존재를 계획하는 것과 지금 모두 실행하는 것을 구분한다.

| 영역 | 역할 | 현재 범위 | 후속 범위 |
|---|---|---|---|
| 브랜드·시각 체계 | 사이트와 채널에 공통으로 쓰이는 정체성 | 기존 모티프 및 선택 시안의 구조 정리, 공식 워드마크 유지 | 실제 색·서체·이미지·레이아웃은 사용자 무드 승인 |
| 매거진·지식 콘텐츠 | 향, 원료, 개발, 실험, 업계, 리뷰의 편집 원본 | 원고 한 개와 근거·공개 범위·연관 엔티티를 한 묶음으로 준비 | 반복 가능한 발행 운영 |
| 웹사이트 | 전체 읽기·관계 탐색·제품 및 서비스 안내의 중심 | 22번 코어와 24번의 Entry → Editorial → Scents 슬라이스 | 23번의 일곱 구간 및 추가 콘텐츠 |
| AFTON 메인 Instagram | 브랜드의 첫인상과 짧은 콘텐츠 진입점 | 공식 계정 확인 항목, 프로필·캡션·연결 목적지 초안, 포스트 형식 계획 | 계정 연결과 공개 권한이 확인된 뒤 발행 |
| 블로그 | 원료·향·공방을 문장으로 충분히 설명하는 창구 | 사이트 Article을 공통 원본으로 재사용하는 계획 | 외부 블로그 필요 여부·플랫폼 확정 후 재편집 발행 |
| 제품·개발·공방 | 실제로 제공할 향과 직접 만드는 서비스 | 현재 확인된 정보와 서비스 구상만 안내 | 선결제 후 리서치·설계, 방문 선택·관리된 배합·포장·수령 |
| 운영·후속 경험 | 문의·사용 안내·피드백·재주문 연결 | 안내 초안 및 경계 정의 | 실제 운영 조건·권한·개인정보 취급 구조 확인 후 별도 구축 |

제안하는 큰 흐름:

Instagram 또는 블로그에서 발견 → 웹 매거진에서 읽기 → 향·원료·기록의 관계 탐색 → 제품 또는 공방 안내 → 운영이 준비된 이후의 주문·방문·수령 → 공개에 동의한 피드백만 다시 편집 근거로 사용.

방문자가 매거진을 전부 읽어야 공방 안내에 도달하는 구조는 만들지 않는다. 공방 안내 직접 경로는 유지한다. 피드백 데이터나 고객 대화를 현재 웹 저장소에 수집하지 않는다.

## 3. 채널별 역할과 미확정 항목

### AFTON 메인 Instagram

브랜드 공식 계정의 핸들·소유 확인·사용 중 여부는 미확정이다. 대화에 나온 `unseenratio`, `sumboy_v_and_v`를 AFTON 공식 계정으로 자동 지정하거나 연결하지 않는다. 새 계정이 반드시 필요하다고 단정하지도 않는다.

준비할 항목: 공식 계정 상태, 공개 프로필명, 소개문 초안, 공식 워드마크 사용, 게시물에서 보낼 실제 목적지, 문의 경로의 책임자. 로그인 정보·복구 코드·토큰·개인 연락처는 이 저장소에 보관하지 않는다.

초기 콘텐츠는 브랜드 입구, 짧은 원료/향 이야기, 공방 방식 안내라는 세 가지 역할로 제한한다. 이는 세 개의 신규 장문 콘텐츠나 매일 세 번 게시하는 요구가 아니다. 기존 공통 원고에서 필요한 부분을 나누는 방식이다.

릴스·상시 스토리·라이브·유료 광고·인플루언서 운영을 첫 공개의 필수 조건으로 넣지 않는다. 화면을 채우기 위한 9칸 피드 제작을 강제하지 않는다. 최종 시각 템플릿은 사용자의 무드 선택을 재사용한다.

### 블로그

블로그를 콘텐츠 기능과 외부 채널로 구분한다. 사이트의 Article/Issue가 장문 원본 역할을 맡는다. 외부 블로그가 필요하다면 같은 원본을 독자가 궁금해할 질문 중심으로 재편집한다. 별도 원고 생산 조직이나 세 번째 신규 디자인 프로젝트로 시작하지 않는다.

외부 플랫폼은 미정이다. 특정 서비스를 선택한 것으로 기록하거나 검색 유입·노출을 보장하지 않는다. 외부 플랫폼 선택이 사이트 코어 구현의 선행 조건이 되어서는 안 된다.

계정이나 외부 목적지가 확인되지 않았으면 사이트에 가짜 소셜 링크나 블로그 링크를 표시하지 않는다. 웹 글이 아직 공개되지 않았으면 후보 브랜치·PR·로컬 미리보기를 소비자용 링크로 배포하지 않는다.

## 4. 한 콘텐츠 원본에서 채널별로 나누기

핵심 운영 단위는 게시물 세 개가 아니라 콘텐츠 묶음 한 개다.

사용자 또는 검증된 출처의 입력 → 공개 가능한 내용만 추림 → 공통 원고와 근거 정리 → 웹/Instagram/블로그 초안 변환 → 사실·연결·이미지 권리 검증 → 공개 권한 확인 후 해당 채널 발행.

| 산출물 | 같은 원본에서 가져올 것 | 채널에 맞춰 바꿀 것 |
|---|---|---|
| 웹 Article | 전체 설명, 근거, 실제 관련 향·원료·기록 | 캔버스의 진입 카드와 읽기 페이지 |
| Instagram 초안 | 핵심 질문과 한두 개의 관찰/설명 | 짧은 캡션 또는 넘겨보는 게시물 문장, 관련 글로 가는 안내 |
| 블로그 초안 | 같은 사실과 핵심 주장 | 질문형 제목, 설명 순서, 소제목, 독립적으로 이해 가능한 본문 |
| 선택적 후속 노트 | 이미 생긴 수정·질문·추가 관찰 | 새 사실이 있을 때만 보충, 새 소재를 억지로 만들지 않음 |

예시 주제: “직접 만드는 향은 방문 전에 무엇을 준비할까?”

- 웹: 공방 서비스 구상과 현재 준비 상태를 설명한다.
- Instagram: 서비스 확인 → 선결제 → 리서치·설계 → 방문 선택·배합·수령이라는 흐름을 짧게 나눈다.
- 블로그: 용도·원하는 인상·알고 있는 향을 왜 묻는지 설명하는 초안을 만든다.

위 예시는 운영 개시나 결제 가능 상태를 뜻하지 않는다. 현재는 서비스 준비 중임을 유지하며 예약·설문·계산이 작동하는 것처럼 표현하지 않는다. 보관·권장 개봉·포장 조건도 실제 검증된 범위만 공개한다.

원료 이야기와 리뷰도 같은 방식으로 재사용할 수 있으나, 실제 시향 경험·실험 결과·조성·안전성·다른 브랜드의 최신 제품 정보는 별도 근거가 필요하다. 요약한다고 추정이 사실로 바뀌어서는 안 된다.

## 5. 늘리지 않을 일과 업무량 상한

운영 리듬 제안: 처음에는 1~2주에 공통 콘텐츠 묶음 1개를 준비해 실제 부담을 확인한다. 이는 일정 예약이나 플랫폼 성장 공식이 아니다. 원고를 만든 뒤 모든 채널에 같은 날 발행할 의무는 없다.

동시에 진행할 주요 작업은 원칙적으로 기술 슬라이스 1개와 콘텐츠 묶음 1개까지다. 모든 카테고리와 채널을 한꺼번에 가동하지 않는다. 급한 정정·보안·운영 문제는 우선 처리하되 그만큼 신규 콘텐츠를 미룬다.

부담이 커지면 먼저 외부 블로그 재편집, 릴스, 추가 게시 빈도를 줄인다. 확인되지 않은 원고를 빨리 공개하거나 사용자가 세 채널 분량을 각각 다시 쓰게 하지 않는다.

사용자가 할 필요 없는 반복 업무: 동일 사실을 채널마다 다시 설명하기, 개별 카피의 반복 작성, 포맷마다 새로운 콘셉트 결정, 이미 결정한 IA 재승인, 매번 상태 확인을 요청하기.

측정할 것은 새로운 대시보드가 아니라 기존 작업 기록의 간단한 항목이다: 원본 준비 시간, 사용자 확인 시간, 수정 횟수, 같은 묶음에서 재사용한 산출물 수. 아직 실측한 값은 없다.

## 6. 분업과 승인

| 담당 | 책임 | 사용자에게 다시 요청할 경우 |
|---|---|---|
| 사용자 | 실제 제작·시향에 관한 경험의 원천, 최종 디자인 무드, 계정 소유·인증에 필요한 본인 조치 | 경험이 기록되지 않아 사실을 확정할 수 없거나 계정 인증이 필요한 경우 |
| 웹 GPT | 큰 맥락 유지, 콘텐츠 구조·원고·캡션·블로그 변환, 근거와 미확정 내용 구분 | 창작 제안을 실제 경험으로 바꿔야 하는 경우에는 추정하지 않고 질문 |
| Codex | 기존 웹 코어·동선·테스트·Git 검증, 승인된 형식 재사용과 필요 최소한의 내보내기 | 실제 접근·도구·권한 차단이 있는 경우 |

정보구조·평범한 카피 수정·데이터 정리는 위임된 범위에서 진행하며 사용자를 매번 편집 실무자로 호출하지 않는다. 원료·상품 주장 등은 근거 검증을 거쳐야 한다. 사용자 개인 맥락은 원고 후보에 넣지 않는다.

게시 권한은 계획 추가와 다르다. 외부 공개가 허용되기 전까지 초안으로 유지한다. 첫 공개 정책을 정할 때 무엇을 묶음 승인할지 명확히 하고, 현재 문서를 자동발행 권한으로 읽지 않는다. 최종 무드 승인과 사실 검증과 게시 권한을 분리한다.

## 7. 최소한의 공통 콘텐츠 기록

새 DB나 별도 관리도구를 즉시 만들지 않는다. 기존 콘텐츠 엔티티와 문서에 아래 필드를 필요할 때 덧붙이는 것으로 시작한다.

- 공통 원본 ID와 버전, 실제 존재하는 Issue/Article/Dossier 참조.
- 주제 유형: 브랜드 안내 / 원료 / 개발·실험 / 업계·리뷰 / 공방 안내.
- 근거와 공개 가능 상태: 확인된 사실 / 관찰·의견 / 구상·후보를 구분.
- 승인된 사용 자산과 출처. 전체 홈페이지 생성 이미지를 실제 로고·제품 사진으로 전용하지 않음.
- 채널별 제목·본문·캡션과 다음 행동.
- 목적지 URL: 확인 전에는 미설정. 링크 가능 여부는 채널별로 확인.
- 채널별 상태: not_started / draft / needs_verification / ready_for_review / ready_to_publish / published / on_hold.
- published에는 실제 확인된 공개 URL·시각·원본 버전이 필요. 원본 변경 시 파생본의 재검토 필요 여부 기록.

한 채널의 published 상태를 다른 채널에 복사하지 않는다. 게시 준비 완료와 실제 게시 완료를 구분한다. 이 기록에는 공개 가능한 내용만 저장하고 원료 처방·고객 기록·계정 비밀은 넣지 않는다.

## 8. 큰 그림 이후의 세부 설계 순서

### 지금 추가한 계획

사이트, Instagram, 블로그, 제품·공방, 후속 안내의 역할을 한 운영 지도 안에 배치한다. 공식 계정과 블로그 플랫폼은 미정 항목으로 남기되 전체 계획을 막지 않는다.

### 다음 기술 결과물
